# 智能营销情报与 IP 研究智能体｜产品需求文档

版本：v0.8 讨论稿｜日期：2026-11-07｜以研究项目贯通全部能力；管理员分配账号、两角色业务功能相同；包含非技术用户上手与如流连接指导。

## Executive Summary｜产品定位

为内部员工提供一个共享的智能营销情报与 IP 研究智能体，包含三条并列工作流：智能营销情报跟踪、IP 研究与持续跟踪、销售研究与建联支持。员工用自然语言提出目标，智能体收集最新可得信息、分析、生成图表和交互成果，并按订阅推送。研究任务可以独立完成，不必转化为商机或联系人任务。

这一版的价值是提高团队情报获取、研究分析和销售准备效率，工具本身不对外收费、不执行交易。“卖点预测”指有证据的待验证假设，不表示销量预测、购买意愿事实或成功保证。员工后续实际销售可在工具外进行。

已确认：内部团队、管理员分配账号登录；第一版包含每日热点报告、IP 资源库、品牌匹配；产品是易操作的智能体，支持图表、可视图和交互界面；承担 IP 分析、可建联对象追踪、联系方式收集；建联对象同时覆盖 IP 方/创作者及品牌营销负责人。Codex 是开发工具；暂无现有应用链接；没有优先平台；本轮仅交付设计文档，不进行正式对外上线或交易。

## Project Overview｜背景与使用者

最新确认：信息应尽可能即时获取；用户可关注 IP，持续跟踪并每日推送到如流，同时支持个人私信与团队群。销售服务覆盖百度营销方案、数字人、云服务及整合营销。具体能力、报价和案例仍需团队录入，不能由智能体自行编造。

进一步确认：网页端也要主动呈现推送；用户为非技术员工，要求直观、交互性强，并支持多种分析和报告导出。本轮同时交付可编辑 Figma 原型；原型只使用明确标注的示例数据，不表示后台功能已实现。

优先级最终确认：IP发展跟踪和预测可合作品牌是最重要功能，决定首页与首轮验收顺序；智能营销情报仍是独立能力；销售支持须覆盖品牌适配、卖点假设、建联对象、联系方式与跟进协作，不因突出IP而削减。

早期讨论包含 IP 授权、数字人直播与分润设想。本产品服务内部团队的营销情报、IP 研究与销售准备，早期商业执行设想不形成第一版交易或直播需求。

现状：已有讨论材料，尚未获得可检查的现有应用或数据接入信息。
目标：员工无需学习提示词技巧或代码，使用一句话或任务模板，即可获得附来源的研究结果、联系人清单和可交互视图，并把结果保存为团队可复用的成果。

| 角色 | 主要操作 | 权限 |
|---|---|---|
| 管理员 | 使用全部业务功能；额外创建、修改、停用账号及设置/重置用户名和密码 | 业务功能与普通用户相同；额外拥有账号管理及后台连接配置权限 |
| 用户 | 使用全部研究、分析、建联、跟进、可视化、订阅、分享和导出功能 | 使用管理员提供的账号；无账号管理权限，不存在只读或简化功能版 |

账号停用后失去访问权限，已有团队研究记录保留。默认内部同一工作空间，不设计外部品牌方门户或公众注册。

## Goals and Objectives｜目标

- G1：减少销售员工分散搜集、重复整理和重复汇报时间。
- G2：建立可持续更新、可追溯的 IP 与文化趋势知识积累。
- G3：帮助员工提出有依据、可验证的品牌匹配与卖点假设，并找到双侧可建联对象。
- G4：让团队以自然语言完成工作，稳定共用成果，并能识别缺失、过期和不可靠数据。
- G5：持续发现关注对象及营销主题的新信息，按个人或团队订阅每日送达如流。
- G6：持续理解智能营销领域的技术、产品、案例与平台变化，形成可独立使用的团队研究积累。

## 三条并列工作流

| 工作流 | 默认研究内容 | 典型成果 |
|---|---|---|
| 智能营销跟踪 | AI 营销技术与产品、数字人应用、营销自动化、品牌案例、服务商/竞品动态、平台能力与规则变化 | 营销情报日报、产品对比、案例卡、事件时间线与主题交互页 |
| IP 研究与跟踪 | 作品/角色/创作者、文化趋势、内容发布、联名合作、热度信号与公开商务变化 | IP 档案、趋势图、关系可视图、关注动态 |
| 销售支持 | 品牌适配、卖点假设、多服务切入点、双方机构与商务联系人 | 商机卡、建联表、跟进记录 |

## 产品对象与核心流程

### 统一研究项目：功能协同的主线

一个研究项目包含研究目标、IP/营销主题、时间范围、来源证据、IP发展画像、候选品牌、适配分析、卖点假设、服务切入点、联系渠道、跟进记录、成果版本与订阅。所有页面引用同一项目及对象标识，避免重复录入和相互矛盾的副本。

主路径：创建项目或关注IP → 收集最新信息 → 形成发展时间线与画像 → 主动发现候选品牌 → 比较适配与合作时机 → 生成卖点/服务假设 → 查找双方角色和商务入口 → 指派跟进 → 导出报告 → 持续跟踪产生下一轮更新。

营销情报路径：订阅主题 → 收集产品/案例/平台动态 → 独立形成专题研究；与某个IP、品牌或服务相关时，员工可“加入研究项目”作为证据，再触发相关分析。不会强行把所有情报转为销售机会。

共同规则：每个结论都可回到证据；每个品牌都可回到推荐理由；每条联系人记录都可回到机构与对应角色；每份报告和通知都引用明确版本。新证据只更新受影响的分析，不重写员工真实跟进记录。

必须分开管理三种对象：

| 对象 | 示例（仅作概念说明） | 用途 |
|---|---|---|
| IP 实体 | 作品、角色、创作者、品牌 IP | 持续研究同一个对象及其别名 |
| 文化趋势 | 穿搭风格、审美表达、情绪主题、流行叙事 | 发现可用于研究的文化元素；不强制归为 IP |
| 来源内容 | 一条笔记、视频、文章或导入记录 | 支持研究判断的证据；不等于可商用素材 |

员工用自然语言或模板提出任务 → 智能体识别目标与范围 → 按已接通来源收集或接收导入 → 整理 IP、文化趋势、机构及联系人 → 分析品牌适配与卖点假设 → 输出带证据的表格、图表和交互研究页面 → 员工保存对象、指派跟进人并记录结果 → 智能体按已设置的关注规则持续更新。

双侧联系人链路：IP/作品 → 权利方或运营方 → 代理/经纪机构 → 商务联系人；品牌 → 公司主体 → 营销/市场/电商团队 → 对应负责人或官方商务渠道。每一条机构归属、代理关系、任职关系均保留来源与核验状态，未知时不自动推定。

联系不到具体个人时，允许以官方商务邮箱、合作表单、机构商务主页作为有效建联入口。公开商务渠道不等于已经联系成功，历史任职也不等于当前负责。

第一版建议默认每天北京时间 09:00 提供日报，时间可配置。该时间是待确认的产品默认值，并非已创建的定时任务。没有优先平台时，由数据接入可行性决定首批来源，不默认小红书或 B 站能直接全量采集。

## 智能体体验与可交互成果

首页建议采用“左侧导航＋中央任务对话＋右侧成果画布”，画布可以全屏。对话用于表达目标和调整结果，成果画布用于阅读、筛选、比较及保存，不要求员工在聊天记录里翻找全部信息。

首屏模板：找 IP 机会、找品牌联系人、分析卖点、生成研究可视图、查看关注动态。输入示例：“帮我研究近 30 天适合年轻服饰品牌的 IP，列出合作理由，找出 IP 商务入口和相关品牌营销负责人，整理成可筛选的表格。”这是任务示例，不代表系统已取得对应数据。

智能体自动推进已具备条件的检索和分析；仅当缺少会实质影响结果的信息时提问，并允许用户修改任务范围。展示“正在查来源 / 正在整理 / 已完成 / 部分完成 / 等待补充”的执行状态，不展示隐藏推理过程。用户可停止未完成任务，已完成结果保留。

| 成果类型 | 适用信息 | 第一版交互 |
|---|---|---|
| 来源表/联系人表 | 可逐条核实的信息和线索 | 搜索、排序、筛选、列显隐、打开原始来源 |
| 趋势折线图 | 有可比历史快照的指标 | 切换对象、指标与时间范围；显示缺失点和统计口径 |
| 对比条形图 | 同口径的候选比较 | 切换维度、查看样本与来源；不混用不同平台原始数值 |
| 关系可视图 | IP、权利方、代理机构、品牌和联系人关系 | 点击节点看档案，点击连线看证据；未知关系不画成事实 |
| 机会矩阵/卡片 | 定性适配与证据情况 | 按匹配程度、证据充分程度和跟进状态过滤，不输出虚假精确分数 |
| 交互研究页面 | 一次任务的综合成果 | 组合摘要、表格和图表；团队内共享，保留版本和权限 |

“生成交互界面”在首版指智能体选择和组合经过验证的组件，生成任务专属研究页面。任意生成并执行网页代码、任意外部数据连接不进入首版。先做上述高频形式，按真实使用反馈扩展。

## Functional Requirements｜功能需求

MUST 为第一版必需，SHOULD 为优先增强，COULD 为可选，WON'T 为本版不做。

### FR-001: MUST — 管理员分配账号与统一业务权限
Acceptance Criteria：
- 仅有管理员和用户两种角色，通过同一用户名/密码页面登录；不开放自行注册、邀请注册或只读角色，用户使用管理员提供的有效账号。
- 管理员可创建账号、修改唯一用户名、设置或重置密码、启用/停用账号；普通用户不能访问这些接口或管理其他账号。
- 两类账号拥有相同的研究、分析、编辑、联系人、跟进、订阅、可视化与导出功能；只在管理员界面额外显示账号管理入口。
- 密码设置后不可明文回看，管理员通过重置来管理；重置或停用使旧会话失效，账号停用停止个人推送，既有团队成果保留。
- 用户忘记密码时获得“联系管理员重置”的清晰提示；错误用户名/密码提示不泄露哪个账号存在；禁止停用最后一个有效管理员。

### FR-002: MUST — 信息收集与来源管理
Acceptance Criteria：
- 支持手工录入来源链接及摘要，以及通过模板批量导入 CSV；导入错误逐行说明。
- 每条信息记录平台、原始链接或来源标识、发布时间（未知时留空）、采集时间及采集方式；明确哪些字段是人工录入。
- 自动接入的数据源必须先通过实际样本验证；无权限或不支持的字段显示缺失，不生成替代数字。
- 相同平台与来源标识的重复导入不产生重复内容；新观测数据可形成新快照。

### FR-003: MUST — 每日研究简报
Acceptance Criteria：
- 每天按配置自动整理已获取的数据，支持管理员手动重跑；报告保留日期、版本和生成时间。
- 每个事实性要点可追溯到来源；AI 推断使用独立标签。
- 页面展示来源覆盖、数据截至时间与失败来源；没有新数据时明确说明，不伪装成当天新热点。
- 日报自动生成不等于自动采集已接通：人工导入模式下明确标识“基于已导入资料”。

### FR-004: MUST — IP 与文化趋势档案
Acceptance Criteria：
- 支持实体类型、名称、别名、标签、来源、研究备注及状态；文化趋势与具体 IP 分类型检索。
- 同名实体不自动合并；模型提出的合并候选需研究员确认，保留变更记录。
- 同一来源可关联多个对象，同一对象可有多个来源。
- 来源内容只作为研究证据；档案不将“已收录”显示为“已获授权”。

### FR-005: MUST — IP发展与持续跟踪（核心优先）
Acceptance Criteria：
- 成员可关注或取消关注对象，查看个人关注列表与团队档案。
- 按时间展示新增来源、可取得的指标快照、备注变化和最后成功更新日期。
- 只有存在同口径历史数据时才计算增长；首次采集显示“建立基线中”。
- 缺少播放量、收藏量等指标时不按 0 处理，页面说明可用指标范围。
- 发展时间线同时包含新作品/角色、内容方向、可获得的受众线索、历史合作和阶段性事件；将单次热点与持续发展区分。发展阶段是带证据的研究判断，缺乏历史时显示“尚无法判断”。

### FR-006: MUST — 合作品牌发现与可解释推荐（核心优先）
Acceptance Criteria：
- 支持两种入口：从IP主动发现候选品牌，以及从已有品牌画像反查IP；主动发现不限于员工已录入品牌，可指定品类、区域、价格带和排除名单。
- 候选由可访问的品牌公开资料、产品与营销活动、历史合作等形成，每个候选都提供“为何适配、为何现在考虑、可能合作形式、疑点、证据来源和日期”；未知项明确留空。
- 适配分析至少覆盖人群线索、品类/使用场景、风格价值观、价格/渠道、历史合作及当前活动信号，先过滤明确冲突，再按证据与适配优先级给出短名单。
- 推荐仅表示值得验证的合作可能性，不等于品牌合作意愿或采购概率；无可靠数据时不输出成功率、预算或销量。无合适候选时允许返回空结果并说明缺口。
- 候选可加入品牌对比、查看公开证据、生成卖点假设、查询双方商务入口、指派跟进或标记不适合；新发展事件触发推荐更新时显示新增/降级理由及版本，人工驳回理由在当前任务中生效。

### FR-007: MUST — 卖点假设与验证建议
Acceptance Criteria：
- 输出包含目标人群、使用场景、需求假设、建议表达、证据、反例或疑点及验证方法。
- 可验证的来源事实、员工输入和 AI 推断分开呈现；禁止将推断包装为真实调研结果。
- 未提供销售历史与真实验证标签时，不输出销量、转化率预测或购买概率。
- 不生成未经输入或证实的产品性能、材质、价格与功效陈述；缺失信息列为待补充。

### FR-008: MUST — 任务状态与异常可见
Acceptance Criteria：
- 管理员能看到各数据源、整理和报告任务的成功、部分成功、失败状态，以及最近一次成功时间。
- 单一来源失败时其余来源仍可产出；报告明确缺失范围。
- 可重试失败任务且不会重复创建同一批次的数据或覆盖已有报告版本。

### FR-009: SHOULD — 研究反馈
Acceptance Criteria：
- 对匹配结果与卖点假设支持采纳、待验证、存疑、驳回四类反馈及理由。
- 记录反馈人、时间、结果版本；修改反馈保留记录。
- 反馈仅用于质量评估与后续规则调整，不自动当作真实销售成效。

### FR-010: MUST — 分析与报告导出
Acceptance Criteria：
- 支持日报、专题研究、IP分析、营销案例和商机研究导出为 PDF 或 Word；表格导出 Excel；单张图表导出 PNG。导出界面按成果类型提供适用格式，具体实现先后顺序在开发计划中确定。
- 导出前可选日期范围、对象、章节和是否包含图表，并预览；长任务显示准备中、完成下载或失败重试。
- 保留标题、生成日期、数据截止时间、统计口径、来源、事实/推断标签与缺口；交互图表在文档中提供静态快照和有权限的网页入口。
- 导出只含当前用户有权查看的资料；联系人字段默认不进入通用研究报告，单独导出线索表时明确展示所选字段。
- 验收样例包含中文、多页表格、长来源链接和图表，确保分页、可读性及数据一致；导出失败不影响网页原成果。

### FR-011: MUST — 自然语言任务与智能体执行
Acceptance Criteria：
- 支持从自然语言或首屏模板发起收集、分析、跟踪及联系人查找任务，显示识别出的范围和任务进度。
- 资料充足时自动推进；缺少关键条件时提问；无法接入的数据源明确说明限制，不宣称已完成检索。
- 支持在原任务中追加“换成图表”“只看品牌方”“按品类筛选”等指令，继承明确的任务条件。
- 用户可停止任务、重试失败步骤并查看部分成果；任务级费用及调用次数受配置限制。

### FR-012: MUST — 可视化与交互研究页面
Acceptance Criteria：
- 同一任务可生成表格、至少一种对比图表和组合式研究页面；有可比历史数据时才生成趋势图。
- 图表标明时间范围、样本量、统计口径和来源；点击相关条目可追溯证据，缺失值不作为 0。
- 支持筛选和切换视图；纯展示筛选无需重新请求模型。改变数据或分析范围时创建新分析版本。
- 可将成果保存并分享给有权限的团队成员；分享链接不绕过登录与角色限制。

### FR-013: MUST — 双侧可建联对象与联系方式
Acceptance Criteria：
- 同时支持 IP 权利方/代理/创作者商务与品牌市场/营销/电商侧线索；具体人未知时可记录官方商务渠道。
- 每条线索记录对象、机构、职务或渠道类型、来源链接、采集时间、最近核验时间和核验状态；来源未说明的任职或关系留空。
- 联系信息仅来自公开用于商务的渠道、获准使用的数据服务或员工有权导入的资料；不猜测邮箱、不采集私人联系方式，也不把个人普通账号自动标为商务渠道。
- 同名人员不直接合并；跨机构关系、代理关系可记录有效时间与冲突说明；失效信息保留历史但不作为当前有效入口推荐。
- 支持查看来源及人工核验；“已找到渠道”“来源已核验”“已联系”“已回复”分别记录，不以格式正确或网页存在宣称能够联系成功。

### FR-014: MUST — 建联对象跟踪与协作
Acceptance Criteria：
- 可为线索指定负责人并记录待核验、待联系、已联系、已回复、暂缓、不适合等跟进状态；默认待核验。
- 能记录最后跟进时间、备注和下一步事项；是否已联系、是否回复由员工实际记录，不由模型臆测。
- 对关注线索按配置重新核查公开商务入口和任职证据，展示变化与待核实冲突；来源不可访问时不自动判定联系人已离职。
- 发现成员重复跟进同一联系人时显示已有负责人和最近状态；本版不自动发消息、拨号或提交合作表单。

### FR-015: SHOULD — 可追溯关系可视图
Acceptance Criteria：
- 将 IP、机构、品牌、联系人及有证据的关系绘制为可点击的关系视图。
- 每条关系可查看来源、更新时间和核验状态；推测关系单独标识且默认不混入事实关系。
- 允许按 IP侧/品牌侧及机构筛选；无关系证据时返回空状态，不生成看似完整的关系网。

### FR-016: MUST — 最新信息刷新与新鲜度
Acceptance Criteria：
- 主动查询“最新”时刷新已接通来源，展示执行状态；每条结果记录发布时间、采集时间、最近成功刷新时间和覆盖来源，不能将静态缓存标为实时。
- 各来源配置实际可达到的刷新阈值；超时、接口失败或配额不足时明确显示过期状态和旧结果日期。
- 区分事件发生、原文发布与系统首次发现的时间；新发现的旧消息不能称为今天发生。
- 人工导入资料单独标识；联系人最近采集与任职/渠道最近核验分开记录，不因页面仍存在便宣称任职仍有效。

### FR-017: MUST — 持续跟踪技能
Acceptance Criteria：
- 支持通过对话或按钮关注 IP 或智能营销主题、产品、机构，配置别名/关键词/排除词、关心事件、来源范围、刷新档位、发送时间与个人/群目的地。
- 用户关闭网页后任务仍运行；多人关注同一对象可复用采集，但分别维护各自订阅和可见范围。
- 首次关注提供背景摘要，之后按来源与事件去重，区分新增、实质更新、纠正和历史补收；重复转载不反复作为新事件推送。
- 支持暂停与取消；停用账号停止个人投递；暂停后不再派发新推送任务，历史成果保留。

### FR-018: MUST — 如流每日私信与群推送
Acceptance Criteria：
- 同时支持员工个人私信与团队群；个人账号绑定和群目的地分别配置、分别完成实际验收，不以群机器人可用替代私信能力验证。
- 个人摘要只含该员工订阅，群摘要只含显式共享给该群的关注列表；启用时显示目的地、发送时间和内容范围，之后按配置自动运行。
- 摘要包含数据截止时间、最新动态、来源、商机假设和完整研究页入口；无新动态可发送一条简短状态或按用户选择静默，采集失败不能作为无动态处理。
- 记录待发送、接口已接受、失败、状态未知与重试信息；接口接受不等于已读；推送失败可重试且避免对已确认成功的消息重复发送。
- 群消息不默认展开联系人明细或个人跟进备注；网页链接继续要求登录并检查权限，群内摘要按共享范围过滤。

### FR-019: MUST — 多服务商机分析
Acceptance Criteria：
- 支持维护营销方案、数字人、云服务、整合营销等服务卡，包含实际能力、适用客户、场景、限制和获准使用的案例。
- 每次分析可选择一种或多种服务；未选择时提出适配建议并说明理由，不向每个对象机械推荐全部服务。
- 商机卡按“观察到的信号 → 可能需求 → 可匹配服务 → 应找角色 → 建联切入点”组织内容，并标注来源和推断。
- 不编造客户预算、采购计划、服务能力、报价与案例；未知项列为待补充。

## 新鲜度与推送规则

### FR-020: MUST — 智能营销情报研究与跟踪
Acceptance Criteria：
- 支持独立订阅智能营销主题、产品、服务商、品牌案例或平台动态；员工无需先选择品牌或销售服务。
- 信息分类至少包含技术/产品更新、营销案例、品牌动作、平台变化；记录发生时间、发布时间、发现时间及来源，优先引用原始发布。
- 案例卡区分“来源宣称的效果”“可核实的数据”和“智能体分析”；无效果数据时不推断提升比例，产品比较记录版本和比较日期。
- 支持按主题生成每日情报、专题对比图和交互研究页，并按个人或团队订阅推送到如流。
- 仅在用户明确选择业务机会分析时关联销售服务库；纯情报任务不强制找联系人或生成销售建议。

### FR-021: MUST — 网页消息中心与双渠道一致性
Acceptance Criteria：
- 每日摘要和订阅动态写入网页消息中心，支持未读数、筛选、已读及历史查询；网页打开时自动显示新动态，关闭时消息继续保存。
- 网页与如流投递关联同一摘要版本和事件标识；网页刷新不创建重复通知，如流失败不阻止网页查看。
- 网页已读只更新该用户的站内状态，不推断如流已读；两通道发送状态分别展示。
- 默认站内通知，无需开启浏览器系统通知权限；浏览器桌面通知为后续可选能力。

## 非技术用户交互与分析要求

### FR-023: MUST — 首次使用与如流连接引导
Acceptance Criteria：
- 首次登录显示可跳过的三步引导：选择对象、查看结果与依据、关注或导出；提供示例研究，用户无需技术文档即可开始。
- 如流连接采用分步向导，展示是否已由企业开通、本人账号绑定状态、个人/群接收范围和发送时间；如流未连接不阻止网页使用。
- 员工无需填写接口或密钥；尚未开通时提供可复制的管理员申请说明，并允许稍后连接；管理员帮助解释目标群机器人设置和测试步骤。
- 在启用前展示明确目的地，用户触发测试消息并确认收到后开启订阅；失败分别提示账号未绑定、群未开通、连接失效或暂时发送失败及可执行下一步。
- 产品内常驻“使用帮助”；连接教程随实际如流权限及接入方式更新，不预设一定支持扫码、某种授权界面或所有消息格式。

### FR-022: MUST — 研究项目贯通与上下文复用
Acceptance Criteria：
- 从IP档案进入品牌推荐、合作分析、联系人、报告或订阅时保留项目、对象与时间范围，无需重新输入。
- 同一IP/品牌/联系人使用共享身份及证据关联，项目内的个人备注与团队共享资料按权限区分；另起研究项目不无意继承私人信息。
- 新证据进入后标记受影响的发展判断、品牌推荐和报告为“有更新/待刷新”，重算生成新版本，展示变更原因；旧报告与真实跟进记录不被静默覆盖。
- 网页消息与如流摘要引用相同版本与数据截止点；查看最新版本与查看原推送版本可区分。
- 允许在任意步骤完成研究、保存或导出，员工不必为了报告而强行创建销售线索；空数据、无合适品牌、找不到联系人和来源失败均有可执行的下一步。

首页以“今天想了解什么？”为入口，提供“了解营销动态 / 研究一个IP / 找合作联系人 / 生成报告”模板。新用户通过选择目标、对象与时间范围即可开始；后续可以直接用自然语言调整。

普通员工界面不出现密钥、Webhook、模型参数、任务队列等实现术语；来源配置与技术连接由管理员完成。任务过程用“查找资料、整理对比、生成结果”描述，失败时说明影响和可执行动作，例如“这个来源暂时未更新，可先查看其余结果”。

分析方式包括主题综述、事件时间线、同口径趋势、对象对比、案例拆解、品牌适配、卖点假设和关系图。智能体选择适合当前数据的视图，员工可切换表格/图表、筛选、点开证据、继续追问、保存或导出。没有足够历史或同口径数据时，不生成不成立的趋势比较。

首次使用目标：5 名非技术试用者中至少 4 人，在不阅读技术文档且不接受现场操作指导的情况下，于 10 分钟人工操作时间内完成一次模板研究、切换视图、关注订阅并导出报告。外部等待时长单独统计；按钮、加载、空数据、部分失败、导出完成等状态均需有可理解反馈。

“即时”的产品含义是主动查询时获取最新可得数据，后台按来源支持的频率持续更新。建议刷新档位为 15 分钟、1 小时或每日，仅开放实际权限、成本和配额支持的档位；最终频率在数据接入验证后确定，不承诺全网秒级覆盖。

每日发送前执行刷新或核验。建议北京时间 09:00 发送，时间可改；每条摘要展示数据截止时间、未更新来源及最近成功时间。若刷新尚未完成，发送有明确缺口的部分摘要或延迟状态，不能把过期数据称为最新。

关注事件建议包含新作品/内容、联名合作、品牌活动、商业动态、可观测热度信号、商务渠道与相关任职变化。即时重大变化通知是后续可选能力，本版先完成每日推送。

| EPIC-006 双侧建联 | STORY-006：作为销售员工，我希望找到 IP 侧和品牌侧的可靠商务入口并分工跟进，减少重复找人 | 已发现公开商务线索；核验并指派负责人；记录来源、核验情况及实际跟进状态 |
| EPIC-007 持续跟踪与推送 | STORY-007：作为员工，我希望关注 IP 后每天在如流收到新增动态 | 已绑定目的地并启用订阅；到发送时间；收到增量摘要或明确的数据异常状态 |
| EPIC-008 多服务商机 | STORY-008：作为销售员工，我希望针对实际服务找出合作切入点 | 已有服务卡及证据；分析机会；获得可能需求、适配服务和应找角色 |
| EPIC-009 智能营销情报 | STORY-009：作为内部员工，我希望持续了解智能营销变化，形成独立研究判断 | 已订阅营销主题；出现新产品或案例；获得附来源的情报、对比及如流摘要，无需创建商机 |

## Prioritization Summary｜版本边界

- Must：FR-001～FR-008、FR-011～FR-014、FR-016～FR-020，覆盖智能体、营销情报、IP研究、可视化、建联、最新信息、持续跟踪、如流双通道与多服务商机；按阶段交付，缺少私信或群推送不能宣称完整满足本版。
- Should：FR-009、FR-015，建议随试点加入研究反馈与可追溯关系图。
- 导出 FR-010、网页消息 FR-021、研究项目贯通 FR-022、上手与连接引导 FR-023 同为 Must；关系图 FR-015、反馈 FR-009 为 Should。PPT导出、浏览器桌面通知和重大事件即时提醒为 Could，暂不纳入首轮验收。
- Won't：直播执行、数字人生成、订单、佣金与分润、支付、公众注册、向潜在客户自动外联、自动洽谈授权、全网秒级监控、未经验证的销量预测、任意生成代码的执行。配置后的内部如流推送属于本版。

## Success Metrics｜效果评估

核心验证增加两项：①IP发展时间线抽样核实事件、日期、实体关联与历史连续性；②由团队准备至少10个代表性IP及已知品牌适配/排除案例，盲评推荐前5个候选的研究价值、依据完整性与明显冲突。目标暂定至少60%的已评估候选“值得进一步验证”，所有候选提供证据或明确未知项；先建立基线再校准目标，不把推荐采纳率等同成交概率。回看历史时只使用当时可得信息，避免利用未来事件形成虚假的预测效果。

先建立 1 周人工流程基线，再进行建议 2 周的内部试用。以下目标为待确认的试点目标。

| 指标 | 基线 | 建议目标 | 测量 |
|---|---|---|---|
| 整理一份可用研究简报的人工时间 | 待测 | 相比基线减少 50% | 同类任务计时，含人工纠错时间 |
| 证据可追溯率 | 待测 | 100% | 每周抽查 50 条事实性结论 |
| 有效研究建议比例 | 待测 | ≥ 60% | 员工标记“值得继续研究”的建议数 / 已评估建议数，报告样本量 |
| 关注对象维护效果 | 待测 | 所有关注对象显示更新时间与可用数据状态 | 每周检查；不要求每个对象每天产生新内容 |
| 需要验证的假设沉淀 | 待测 | 每周至少形成 5 条经人工筛选的假设 | 去重后计数，并记录后续验证动作 |
| 建联线索准备时间 | 待测 | 相比人工基线减少 50% | 同类目标从提出任务至形成经人工核验的线索清单，包含核验时间 |
| 联系渠道可追溯率 | 待测 | 100% | 抽查来源、采集及核验状态；回复率单独观察，不预设承诺 |

不将“有用”“采纳”视为卖点已被市场验证，不以 GMV 或利润考核这一版。

## Assumptions and Dependencies｜假设与依赖

销售服务类别已确认覆盖多类服务，具体能力和案例待录入。其他未确认项：人数、首批数据来源及访问权限、研究主题、品牌样例、预算、内部环境、历史数据、日报时间、如流应用权限和身份绑定方式。

| 依赖 | 当前状态 | 推进方式 |
|---|---|---|
| 可持续的信息来源 | 未确认接口或采购条件 | 先验证一个来源的真实样本；并行保留手工/CSV 输入 |
| 团队研究方向 | 无优先平台 | 先确定主题与品类，避免无范围地收集全网 |
| 品牌画像 | 尚未提供 | 可使用清楚标注的假设画像进行设计演示 |
| 模型服务和内部环境 | 待定 | 由可访问性、费用和组织要求选择，不预设已有账号 |
| 如流双通道 | 两种都需要，尚未接入 | 单独验证群消息、个人消息、身份绑定、网络可达性与格式 |
| 现有小应用 | 无链接可检查 | 暂按独立产品设计；后续有现有成果再评估复用 |

## Constraints｜设计约束

- 本轮只设计，不构建或部署应用。
- 数据覆盖以实际验证的来源为准；模型不承担凭空补全实时数据的职责。
- 暂按单个内部团队设计；不同团队隔离、外部品牌账号和公众版本不进入首版。
- 发布时间、成本和技术栈在数据验证与内部环境确认后评估。

## Out of Scope｜本版不做

不实现直播间、数字人音视频、商品交易、IP 商务合同、分润结算或公开网站运营。商务联系人和跟进记录属于本版；自动外联与完整 CRM 不属于本版。授权状态可作为研究备注，但不建设授权审批系统。数据收录不构成素材使用许可；第一版保留来源与研究摘要，不建设原视频和图片搬运库。

## Risks and Mitigations｜主要不确定性

| 风险 | 对产品的影响 | 处理方式 |
|---|---|---|
| 平台接口不支持全站热点 | 自动采集范围不足 | 首先验证数据源；无法接入时显示导入模式，不承诺双平台全覆盖 |
| 不同平台指标与样本不同 | 排名或增长具有误导性 | 分平台、分时间窗展示；跨平台综合分暂缓 |
| 同名 IP、转载或营销内容 | 错误归并、重复证据 | 别名表、来源去重、人工确认及异常标记 |
| AI 给出缺乏依据的卖点 | 团队误把猜测当事实 | 引用校验、事实/推断标签、疑点与验证方法 |
| 初期没有历史数据 | 无法计算真实趋势 | 从首日建快照；有可比数据后再显示趋势 |
| 联系人与机构关系过期或重名 | 联系错对象或团队重复跟进 | 核验时间、来源与关系版本并存，人工确认和负责人提示 |
| 智能体任务范围无界扩大 | 执行时间与费用不可控 | 明确任务范围、查询/调用限额、停止能力及部分成果 |
