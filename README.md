# CUE — Marketing & Culture

供内部共享的营销、品牌、商业 IP 与文化消费信息平台。React + Node.js + SQLite，无账号、个人收藏或个人关注功能。

## GitHub 网页预览

预览地址：[CUE 网页](https://lichang1125.github.io/cue-marketing/)。GitHub Pages 使用 `gh-pages` 分支发布现有真实内容快照；首页标注快照时间，搜索限当前内容，暂不自动更新。完整实时版仍由腾讯云后台提供，等待域名、备案和 HTTPS 开通。构建与切换步骤见 [Pages 发布说明](GITHUB_PAGES.md)。源码仓库已按用户批准公开，不包含平台凭据和数据库。

## 推荐共享部署

推荐 GitHub + 国内云厂商常驻 Linux 云主机 + Docker Compose，使用免费 OpenCLI/CDP 和持久化浏览器会话。完整步骤与实测边界见 [部署说明](DEPLOYMENT.md)。访客无需扫码；首次服务器登录、会话失效验证仍由管理员完成。

## 本地运行

Node.js 22.13+，推荐 Node.js 24。

```sh
npm ci
npm run build
npm start
```

访问 http://127.0.0.1:4173 。HOST、PORT、DATA_DIR 可指定监听地址、端口与持久化目录。

## 页面与交互

- 视野：带原配图的近期营销新闻与跨来源热榜。行业报道优先，过滤抽奖、促销、饭圈和混乱标题；小红书和抖音分别保留合格内容位置。来源筛选使用完整候选池，避免被全局前 60 条截断。没有日期的近期平台线索不伪造发布时间。
- 精选：直接读取 radar.brandstar.com.cn 的分类和分页，按原站日期分组。全部、趋势、洞察、案例、营销、空间、人物、资讯共 8 类；网页去掉站点来源标注，后台保留来源与原文链接。页面每分钟检查，后台缓存 5 分钟；读取失败不替换为虚构新闻。转载内容从摘要页解出实际发布媒体地址，原文链接和图片映射持久保存到 DATA_DIR/article-assets.json；原图保存在 DATA_DIR/media。精选、日报、首页、详情与案例卡共用原文入口，不跳到品牌星球摘要页。品牌星球原创文章保留，并允许直达 /articles/ 首发页面；/select/ 摘要页仍不作为原文链接。
- 趋势观察：主题搜索与趋势总览合并为一页。默认按品牌营销、IP 联名、潮玩消费汇总；输入主题并回车，会自动在已连接的平台搜索，并汇入公共主题目录。
- 主题结果：先显示已有的相关内容，再补齐跨平台结果。香水扩展香氛、香薰；亚文化扩展哥特、朋克等圈层词。实际平台互动来自公开样本，不能代表全网讨论量。
- 可交互图表：脉动按品牌营销、IP 联名、潮玩消费切换。主题搜索直接显示平台互动指标；可切换平台、指标、7/30 天、折线/柱状图，并查看底层内容。使用固定内容样本的实际观测，不再把收录条数当成关注趋势。单次读数只显示一个点，缺少数据不补零。
- 营销看板：公共热点分布图和营销案例。点击热点板块筛选案例，营销思路只提供可借鉴的角度，不虚构销量或传播成效。
- 所有新闻组件都有封面：先从原文提取 Open Graph / Twitter 图片及正文图并本地缓存，再尝试原始远程图片；确实无图或加载错误后才用主题备选图。取消旧版 8 秒超时替换，避免懒加载图片尚未进入视口就被换掉。原创封面与提示词见 public/covers/README.md。

网页只显示内容与必要的阅读数据，不显示采集时间、下次检查时间或后台运行规则。前端不读取或保存个人收藏、关键词和跟进偏好。右上角为百度图标与“泛科技通用拓展二组内部使用”，无数据来源入口；这是一条展示文字，不构成访问权限控制。

## 趋势口径

server/insights.js 汇总真实案例和观测。全局营销案例与宽泛主题线索区分：用户分享可进入相关主题，个人偶遇、交易招揽等不充当营销新闻。招聘、军事和无关娱乐内容被排除。

- 全局案例范围为近 7 天发布；重复标题和同链接去重。
- 互动变化须同一内容、同一指标至少两次观测，相隔至少 10 分钟；只使用最近 24 小时且来源仍有效的记录。
- 聚合互动只在同来源、同指标内进行。至少 3 个可比较样本，其中至少 60% 增加且合计为正，才标注互动升温；不足时持续观察。
- 周环比需要同来源的历史基线，不将第一次批量导入当成增长。
- 热点图的数字是相关案例数，主题可交叉，不是虚构的热度指数。

## 网站内置日报

- 按 Asia/Shanghai 时区，每天 08:00 生成当天一期并持久化。
- 范围为北京时间昨日 00:00（含）至今日 00:00（不含）。
- 顶部重点速览，下分品牌与公司、联名与 IP、新品与消费、平台与营销。
- 正文使用来源中的事件摘要/短摘录；每条有来源和原文链接，缺少依据不补写细节。
- 日报新闻来源为 SocialBeta 和品牌星球，平台相关线索另行归类。
- 重启后补生成缺失的当期日报；失败重试，内容不足或来源部分失败每 15 分钟重试。
- 维护命令：npm run report:daily -- --refresh；输出 SQLite 和 data/reports/YYYY-MM-DD.json。
- 可用 node scripts/import-report.mjs <文件> 导入编辑版，自动任务不会覆盖。

部署须保持 Node 服务持续运行，并持久化 DATA_DIR。上传 GitHub 只保存代码，不会自动启动后台。数据、平台会话和测试材料已通过 .gitignore 排除。

## 数据接入

公开来源为 B站热门、SocialBeta、品牌星球，每 5 分钟检查；泛娱乐动画榜已退出默认采集。本地模式的小红书、抖音、微博、知乎和 B站主题搜索使用 OpenCLI 只读适配器，需采集机器的 Chrome 扩展及平台会话有效。

先运行 `npm run sources:install` 注册仓库内的只读适配器，再连接 OpenCLI Chrome 扩展。适配器需要与本仓库的 node_modules 保持相对位置，详见 adapters/zhichao-sources/README.md。

平台定期检索品牌联名，公共主题每轮完成约 15 分钟后补充。搜索请求不需要选择平台。重复搜索复用当前任务和近期缓存；同时轮询最多 8 个公共主题，新主题替换最久未搜索的活跃主题，已有内容仍可查看。平台任务串行执行，忙碌时排队；前端每 10 秒读取更新。

类别搜索扩展关联词：香水同时检索香氛与香水新品，亚文化补充哥特、朋克、二次元文化。各平台请求最多 30 条（实际受平台返回数量限制）；B站按发布时间检索并追加第二页。行业资讯扩展至 6 页及趋势、洞察、原创分类，修复遗漏原创文章的问题。微博中文月日时间、知乎原始创建时间用于日期统计；小红书搜索适配器从笔记 ID 推算的日期不计作已核实发布日期。数据库保留 30 天内收录记录，取消旧版 1,000 条读取截断，避免扩展检索后早期主题被挤出统计。相关内容总数不等于全网讨论量，抖音累计播放单独展示。

这些是定时查询，不是官方实时推送。第三方限流、登录失效或页面变化会导致暂时不可用，后台会保留状态并重试。抖音话题累计播放量不当作单条视频播放量。
